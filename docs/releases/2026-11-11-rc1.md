## 复现与剩余条件

在插件 checkout 运行，输出目录必须不存在：

```powershell
../../.venv/Scripts/python.exe scripts/verify_regression.py `
  --archive ../dist/dsh-mineru-win7-0.1.0-rc.1-20261111.zip --output <新回归目录>
```

双架构入口为 `scripts/verify_offline.py`，按 [离线指南](../offline-testing.md)
传入上述 Portable、同一插件 ZIP、Node、Chromium 和 Playwright 路径。然后按
[发布指南](../release.md) 用 `scripts/check_release.py` 汇总；增加 `--require-stable` 后应拒绝当前证据。
最终强制门槛的 invocation.json / gate.log 保存实际命令、Python 退出码与输出。

前一个候选 ZIP `...-rc.1-candidate.zip` 通过 126 项测试及双架构离线检查，
但复核发现 Win7 SP1 判断需收紧，所以生成上述新 ZIP，新增 7600 拒绝用例并完整重新验证。
早期目录 `.out/rc1-regression-20261111/`、`%TEMP%/mru-rc1-x64-1111/` 等保留原始记录，
不与最终包拼接成验收证据。

仍缺真实 MinerU legacy Tasks + Office Gateway 服务上的协议和识别质量证据、
Win7 SP1 实机运行/浏览器证据。模型自动选工具未实测，本地 jobs 检查没有调用 LLM。
完成外部验收后才选择正式版本号；新正式 ZIP 必须重新绑定全部证据，不能沿用本 RC 的哈希。
本机不部署 GPU 服务，不创建 GitHub Release。
